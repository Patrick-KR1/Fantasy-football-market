# 가격 발행 검사 기간 수정

`report-v3` 가격 계산은 `valuationStartMs` 이후에 종료된 경기만 사용하지만, 발행 검사는 시즌 전체의 오류로 가격을 보류했다. 그 결과 가격에 반영하지 않는 과거 경기의 스코어·카드 오류가 현재 가격 발행까지 막았다.

`20261108090000_launch_scoped_publication_guards.sql`은 두 보류 조건을 실제 가격 반영 기간과 일치시킨다.

- 종료된 경기의 오류로 발행을 보류하는 조건.
- 이전 정상 점수가 불완전해지는 경우 기존 가격을 보호하는 조건.

두 조건 모두 `kickx_report_plan`과 같은 `kickx_fixture_valuation_at` 종료 시각과 시작 경계 포함(`>=`)을 사용한다. 시각이 불명확하면 보류를 유지한다. 시작일은 정책 값에서 읽으므로 날짜를 함수에 고정하지 않는다. 기존 `form-v2`·프로토타입 분기는 변경하지 않는다.

과거 경기의 오류 기록은 그대로 남는다. 초기 가격·고정 기준점·가격 공식·미출전 −1.5%·원천 변경 감지·역할 권한은 변경하지 않는다. 가격에 반영되는 기간의 오류는 계속 발행을 보류한다. 이번 변경은 이후 경기의 오류를 건너뛰는 정책이 아니다.

## 검증

- 단위 테스트 287개 통과.
- 모든 마이그레이션을 적용한 임시 PGlite DB에서 SQL 통합 테스트 37개 통과.
- 신규 `database-publication-launch-scope.sql`: 과거 오류 2건을 유지한 채 정상·미출전 가격 발행, 고정 초기값·가격 이력 보존, 과거 정상 기록의 오류 전환 허용, 정확한 시작 경계의 새 오류 보류, 이후 정상 기록의 오류 전환 시 기존 자산 가격 보호.

## 운영 적용

마이그레이션은 함수만 변경하며 가격이나 재계산 큐를 직접 수정하지 않는다. 운영 반영 시 이 파일을 기존 마이그레이션 흐름으로 한 번 적용한 후, 보류 선수는 정상 계산 작업으로 재검증한다. 최신 원천 자료로 결과가 달라질 수 있으므로 과거의 예상 인원·가격을 그대로 발행하지 않는다. 애플리케이션 코드 변경이 없어 이 수정 자체를 위한 별도 Vercel 배포는 필요하지 않다.
