# Claude 인계: 선수 시장 범위·목록 배치·페이지 이동

2026-10-31 사용자 요청 기준. 범위와 탐색 통합에 이어, 선택 영역을 목록에 붙이고 통계 영역 삭제·카드 페이지 확장·번호 입력 이동까지 반영한 현재 인계다. 기존 로고·전체 폭 레이아웃·홈 영문 문구·페이지 입력 카드 등 앞서 Claude가 반영한 디자인을 사용한다.

## 1. 집계 범위 수정

등록 선수 목록은 이미 5대 정규 리그로 제한됐지만, 시장 배너는 전체 구단·대회 사전을 세고 있었다. 기존 거래 가능 인원은 DB 전체에서 가격이 있는 선수를 세면서 가격 확정 여부도 확인하지 않았다.

| 항목 | 수정 전 | 수정 후 확인값 |
| --- | ---: | ---: |
| 정규 리그 | 14 | 5 |
| 구단 | 223 | 96 |
| 등록 선수 | 2,901 | 2,901 |
| 거래 가능 선수 | 3,260 | 2,553 |

수정 후 수치는 2026-10-31 18:25 KST DB 확인 기준이며 이후 수집·가격 확정·경기 상태에 따라 바뀐다. 숫자를 화면에 고정하지 않는다.

시장 배너의 구단 수, 리그 수, 리그 선택 타일은 현재 소속 구단의 리그가 `bsd-1`, `bsd-3`, `bsd-4`, `bsd-5`, `bsd-6`인 범위로 표시한다. 컵대회와 유럽 대회 타일은 선수 시장에 표시하지 않는다. 다른 구단의 상세 정보를 읽는 데 필요한 전체 구단·대회 사전은 유지한다.

## 2. 거래 가능 선수의 의미

`kickx_market_summary()`가 등록 선수와 같은 범위를 집계한다. `totalPlayers`는 그 범위 전체, `readyPlayers`는 가격이 있고 `pricing_status='ready'`이며 선수 거래 정지가 없는 인원이다. `pricedPlayers`는 여기서 경기 전후 거래 제한에 걸린 인원을 제외한 값이다.

경기 제한은 기존 주문 검사와 같은 기준을 사용한다. 정규 리그 경기 시작 90분 전부터 종료 확인 후 10분까지이며, 구단 또는 해당 경기 통계에 나타난 선수와 연결한다. 집계는 활성 경기를 한 번에 찾고 제한 선수를 묶어서 계산한다. 선수마다 전체 경기 목록을 재조회하지 않는다.

시장 전체 거래량과 상승·하락 집계도 동일한 선수 범위를 사용한다. 상승·하락에는 가격 산정이 완료된 선수만 포함한다. 이번 변경은 집계 함수 수정이며 선수 가격이나 거래 원장을 다시 산정하지 않는다.

추가 요청으로 시장 중간의 전체 거래량·상승 선수·하락 선수·거래 가능 선수 통계 카드 영역을 통째로 삭제했다. 데이터 미준비 시 나타나던 대체 안내 영역도 삭제했다. 이 집계 함수는 공통 상단 바 등에서 계속 사용하며, 회원별 잔액·중복 보유 등 개별 주문 조건은 기존 주문 단계에서 확인한다.

## 3. 문구 수정

- 배너의 `실제 경기 기록으로 움직이는 선수 가치. 관심 선수를 모아두고 가치가 열리는 순간을 기다리세요.` 문장을 삭제했다.
- `최근 움직임`을 `최근 변동`으로 바꿨다.
- 선수 시장 제목 아래의 `경기의 흐름을 읽고, 가치가 움직이는 순간을 잡으세요.` 문장을 삭제했다.
- 선수 시장 제목은 데스크톱 40px, 700px 이하 화면에서는 30px로 키웠다. 변경은 `.market-heading` 안에만 적용한다.
- 영문 보조 제목과 한글 제목의 기존 형식을 유지했다.

## 4. 선수 탐색을 시장으로 통합

헤더 보조 메뉴와 푸터에서 선수 탐색 링크를 제거했다. 공통 검색, 홈 관심 선수, 상세 페이지의 목록 복귀, 규칙 안내, 선수 커뮤니티의 목록 진입 링크는 `/market`으로 이동한다.

`/players`는 `/market`으로 영구 리디렉션한다. 기존 링크의 `q`, `team`, `watchlist` 등 쿼리를 유지한다. `/players/[id]` 선수 상세 페이지와 `/api/kickx/players` 데이터 API는 기존 경로를 사용한다. 선수 커뮤니티의 옛 목록 경로도 시장으로 연결한다.

선수 시장에 보유 선수 탭을 추가해 기존 탐색에서 제공하던 보유 조건을 사용할 수 있다. 관심·보유 목록도 시장에서 조회할 때 5대 리그 범위를 적용한다. 일반 목록은 기존처럼 서버 페이지 단위로 읽고, 개인 목록의 인증과 캐시 분리를 유지한다.

## 5. 선택 영역과 목록 배치

현재 위에서부터 제목 → 메인 배너 → 최근 변동 → 선수 목록 영역의 순서다. 리그 선택 타일을 배너에서 분리해 선수 목록 영역 안으로 옮겼다.

선수 목록 영역에는 리그 타일, 목록 탭·보기 전환, 검색·구단·정렬 필터, 포지션 필터, 조회 결과, 페이지 선택이 이어진다. 선택 타일과 결과 사이에 통계나 최근 변동 등 다른 콘텐츠를 끼워 넣지 않는다. 리그·구단·검색 조건을 바꾸면 첫 페이지로 이동한다.

## 6. 카드·목록 페이지와 번호 입력

- 목록 보기: 한 페이지 12명.
- 카드 보기: 한 페이지 48명. 기존에는 두 보기 모두 공통 상수 12를 사용하고 있었다.
- 처음에는 목록 보기로 열며 데이터 로딩 상태에 따라 보기 방식이 바뀌지 않는다.
- 보기 전환 시 첫 번째로 보던 선수의 위치를 포함하는 페이지로 이동한다. 예를 들어 목록 5페이지의 첫 선수는 카드 2페이지에서 이어서 확인할 수 있다.
- 마지막 페이지는 남은 인원만 표시한다. 현재 페이지와 전체 페이지 수는 선택한 보기의 페이지 크기를 기준으로 계산한다.

홈과 같은 `Pagination` 컴포넌트를 `centered`, `allowJump` 옵션으로 사용한다. 페이지 번호·이전·다음·양 끝 페이지를 제공하며, `…`를 누르면 직접 입력 카드가 열린다. Enter·이동 버튼으로 이동하고, 잘못된 번호는 안내와 함께 요청을 차단한다. Escape·취소로 닫을 수 있다. 페이지를 이동하면 선수 목록 영역 상단으로 스크롤한다.

한 번에 서버에서 해당 페이지에 필요한 12명 또는 48명만 읽는다. 검색·구단·리그·관심·보유 등 기존 조건과 인증·캐시 분리를 유지하며, 전체 선수 데이터를 내려받는 방식으로 바꾸지 않는다. API가 허용하는 페이지 크기 상한 50 이내에서 동작한다.

## 8. 확인 결과

단위 테스트 245개, ESLint, 프로덕션 빌드·타입 검사를 통과했다. 앞선 범위 변경에서는 SQL 통합 검사도 통과했고, 운영 집계의 등록 선수 수는 실제 범위 내 선수 목록 수와 같은 2,901명이었다. 이번 추가 화면 변경은 별도 DB 변경이 없다.

26개 경로를 데스크톱 1440px·모바일 390px에서 검증했고 브라우저 JavaScript 오류는 없었다. 319명의 테스트 전용 응답으로 카드 48명·마지막 페이지 31명, 목록 전환 시 위치 유지, 리그·구단 선택 후 첫 페이지 초기화, 번호 입력 이동을 확인했다. 모바일 페이지 버튼의 가로 밀림도 해결했다. 테스트 선수는 운영 DB에 저장하지 않는다.
